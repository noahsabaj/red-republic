# Red Republic — Planned Economy Builder

Isometric city-builder (React 19 + Vite 7 + TypeScript, canvas renderer). Package manager is **bun** (`bun.lock` is the lockfile — never commit a `package-lock.json`).

## Commands

- `bun run dev` — dev server on port 3000 (`?demo` seeds a developed town, `?seed=N` reproduces a specific map). The port is strict — kill stray servers first.
- `bun run check` — the full gate: `tsc -b && eslint . && vitest run`. Run before committing.
- `bun run test` — Vitest only. **Never `bun test`** — Bun's native runner grabs `*.test.ts` with incompatible semantics.
- `bun run build` — production build (tsc + vite)
- `bun run desktop:dev` — native Tauri window with HMR (starts its own vite on :3000; a browser tab can attach to the same server). `bun run desktop:build` — local installers under `src-tauri/target/release/bundle/`.

## Architecture

- **World + systems + mutations — the shape of the simulation.** The sim used to be one 4,900-line `GameEngine`; it is now three things, and new mechanics go in the third.
  - `src/game/world.ts` — `World`: **all** mutable simulation state (map, buildings, topology, calendar, weather, the republic's measured condition, the fleet, the treasury, standing policy) plus the primitive accessors and queries over it (`def`, `stockOf`, `capOf`, `addStock`, `baseEff`, `productionRates`, `routeBetween`, `dispatchScore`, `collectLogisticsDemands`, …). Also the domain types every system speaks — a system module can name a `Vehicle` or a `Contract` without importing the engine that runs it, which is what stops every extraction from becoming a circular import.
  - `src/game/systems/*.ts` — one module per system, each `export function f(w: World): Mutation[]`. A system reads the world and **returns what it wants to change**; it never writes. Each also exports `WRITES` — the mutation kinds it may emit — and `mutation-writeset.test.ts` fails the build if it emits anything else. That declaration is the whole point: a new mechanic can no longer widen the blast radius of an old one by quietly reaching for a field.
  - `src/game/mutation.ts` — the named `Mutation` union and `applyMutations`, the single writer. Every kind is named after its effect; there is deliberately **no generic `{field, value}` escape hatch** (that is "write anything" with extra steps, and the guard test would have nothing to check). Coarse kinds are correct at a genuine transaction boundary — `exportSale` is stock out + contract credited + treasury paid + ledger booked because that is one border sale and the parts are never emitted apart.
  - `Staged` is for systems that read their own writes: it records a mutation **and** applies it, in emission order. Logistics needs it (serving a destination raises its `incoming`, which lowers what its remaining demands are worth — that feedback IS the load-spreading), as do foreign trade, loans and construction. It is deliberately **not** a copy-on-write overlay: delaying the write buys nothing, because either way every effect passes through `applyMutations` and lands in the returned list. The point was to declare the write, not to defer it. Pass-local scratch (the routing context) is not world state and is not staged.
  - Ordering is load-bearing. Systems emit in source order, the day loop applies in emission order, and `underSystem()` attributes each to its caller. Changing the order of two systems, or of two mutations inside one, changes float accumulation and event ids.
- `src/game/engine.ts` — `GameEngine`: what **runs and exposes** the world, and nothing that simulates it. Fixed-timestep day loop (`advance(dtMs)`, 500 ms = 1 day at 1× speed) sequencing the systems, plus the event drain, the React subscription, saves, player actions and the ~112-member facade the UI reads. All randomness flows through the seeded RNG created from `engine.seed` (deterministic per seed — keep it that way; no bare `Math.random()` in sim code; `mulberry32` exposes `getState()/setState()` so saves restore streams bit-exact). Constructed from `{seed, mapW, mapH, climate, difficulty, name}`.
- `src/game/config.ts` — all game data/balance (buildings, resources, prices, objectives, `CLIMATES`, `MAP_SIZES`, `DIFFICULTIES` — start conditions, plus the one thing the sim really does read every day: the border's `importPriceMult`). Data lives here, behavior in the systems — so **a list of building ids in the sim is a smell, not a shortcut**: a list is a thing you must remember to edit, and whatever you forget lands silently in the fallback bucket. Two of them have been converted; convert the next one the same way, as a per-building property authored next to the fields it relates to, plus a `ui-guards.test.ts` guard so an unauthored building fails the build instead of defaulting quietly.
  - `BuildingDef.unpoweredEff` — what a building does when the grid cannot feed it (0 = stalls dead, default 0.5 brownout), authored next to the load it draws; rejected where `power` is 0. Whatever it does to output, **it must never zero out demand**: `nominalInputRate()` measures intent via `nominalEff()` (power floored at the brownout rate), because a stalled mill that reports needing nothing is never resupplied and the outage becomes permanent.
  - `BuildingDef.allocationPriority` — queue position for the two things the republic hands out in a fixed order, **workers** and **power** (lower first, ties fall back to commissioning order, unauthored defaults behind everything). It replaced `JOB_PRIORITY`, whose real damage was invisible: housing employs nobody, so it was absent from a *jobs* list that also decided the brownout order, and households were therefore the first thing switched off. See the Power Grid rule below — that decision is now the player's, and `allocationPriority` only orders buildings *within* a sector.
- **Who goes dark is the player's call, not the engine's.** A brownout is a political decision — the plan or the people — and a planned-economy game must not answer it for them. `engine.powerSectorOrder` is a player-owned ordering of the four build categories that draw power (`POWER_SECTORS`; `infra` draws none), reordered in the **Power Grid** panel, serialized, and validated as a full permutation on load so a corrupt save can't drop a sector off the grid. the `powerHeat` system walks it, and the sort is three layers coarsest-first: the player's per-building `priorityHigh` flag (the same one that jumps the labour queue — one override, both scarce things), then the player's sector order, then the authored `allocationPriority` inside a sector. `powerGridStatus()` is the engine-owned view the panel renders — draw, served and dark counts per sector — and the UI never recomputes it. The default (`industry` first) is the only order under which the pinned campaign reaches autarky; services-first leaves the Machine Works unbuilt, which is exactly the kind of consequence the control exists to let the player feel.
- `src/game/mapgen.ts` — variable map sizes (32–128 per axis; presets in `MAP_SIZES`). Feature densities scale with area but **48×48 output must stay byte-identical per seed** (same rnd() call order — `mapgen-snapshot.test.ts` is the tripwire; never repin it to make a change pass). Engine/render/pathfind read dimensions from `engine.mapW/mapH`, never from constants.
- `src/game/weather.ts` — `WeatherTimeline(seed, climate)`: deterministic climate per seed (temperature + Markov conditions + snow depth + river freeze), generated sequentially and memoized so `engine.weather` and the exact `forecast()` share one source. Numeric climates live in config's `CLIMATES`; the default `plains` preset is pinned by `climate.test.ts` and must never drift.
- `src/game/save-format.ts` + `src/game/save-slots.ts` — versioned save blobs (`engine.serialize()` / `GameEngine.fromSave()`, packed tile codec, `SaveError`) and the localStorage slot store (manual slots, `quicksave`, rotating autosaves, export/import). The engine never imports the slot store. Entity payloads hydrate over a defaults spread — a new engine field with a sensible default needs no format bump; anything that can't be defaulted bumps `SAVE_FORMAT_VERSION` with a `MIGRATIONS` step. Loads always come back paused.
- `src/game/pathfind.ts` — multi-source weighted shortest-path floods on reusable generation-stamped scratch buffers, lazily resized to the requested map (a resize bumps the generation — stale views must throw, not read zeroed stamps). `floodCost()` is a bucket-queue (Dial's) Dijkstra over small integer entry costs (maxStep 1 ⇒ plain FIFO BFS with hop-count distances); `shortestPathToAny()` is the bounded counterpart that stops at the nearest ranked goal. `maxStep` is validated (`Number.isInteger`, `≤ MAX_SUPPORTED_STEP`) *before* any buffer/gen side effect, and the topology owns it: `TopologyIndex.maxStep(domain)` is the max entry cost the domain's own mask produced, so the pathfinder bound can never disagree with the costs (road/water → 1, land → offRoadStepCost). `FloodResult.distanceAt` returns accumulated travel **cost**; a view is valid only until the next flood — consume it before flooding again.
- `src/game/input.ts` — DOM-free pointer/keyboard gesture state machine (pan/paint/pinch/select, WASD/edge panning; keys: Escape = cancel tool else open menu, **X = arm bulldoze**, Space = pause, 1/2/3 = speed). `GameCanvas.tsx` is a thin Pointer-Events adapter around it; live preferences arrive via the injected `InputOptions` provider.
- `src/game/render.ts` — isometric canvas renderer. Draw order is the row scan: anything world-positioned (buildings, trucks, citizens, placement ghost) must draw at its row inside the scan, never as a post-scan overlay, or it will float over buildings that should occlude it. Status colors come from `STATUS_PALETTES` (default/colorblind); `UIState.reducedMotion` freezes decoration (particles, glints, bob) but never sim-driven movement.
- `src/app/` — the meta-game shell: `screens.ts` (pure reducer over menu/pause screens — exactly one dialog can exist at a time; Escape is a single `BACK` semantic), `session.ts` (`GameSession` = engine + founding config + monotonic id; the id keys `<GameCanvas>` so new-game/load remounts camera+input+debug hook — never swap engines in place), `settings.ts` (typed localStorage store with engine-style subscribe; React reads it via `use-settings.ts`, canvas/input/audio read `getSettings()` live). `?demo`/`?seed=N`/`?climate=` bypass the menu (dev workflow).
- `src/audio/` — procedural WebAudio (zero assets): synth SFX + generative minor-key score + unified interaction sound. **Audio listens, never participates**: it hooks UI callbacks and the single App event drain (`drainEvents()` is destructive — one consumer, fanned out), reads an engine probe, and must never import engine internals or touch sim RNG. Context creation is gesture-gated (`audio.unlock()`). **One catalog, one dispatcher, one owner per moment** — three channels feed the `audio` singleton and nothing double-fires: press (a `click`/keypress → `audio.ui(family)`), outcome (a result → `audio.sfx(name)`), engine event (`onGameEvent`). Press sound has a single owner: a capture-phase delegated listener (`installUiSounds`, mounted once in `App`) classifies any activated control via the pure, node-testable `classify()` in `ui-catalog.ts` (`ElementDesc` descriptor, never a live DOM node — the test env is `node`, no jsdom) and plays a mechanical **in-key** voice from `UI_VOICES` (bodies pitched to the score's live chord via `clickHz`+`MusicEngine.currentChord()`; noise stays unpitched). Controls opt out with `data-sfx="none"` when their result/funnel already sounds (trade, build-tool arm); keyboard nav calls `uiSound(family)` — same dispatcher. Three buses (music/effects/**interface**) with independent volumes; menu families ride interface, world cues (`select`/`toolArm`/`toolCancel`) ride effects (`FAMILY_BUS`/`SFX_BUS`). Adding a control needs no wiring — untagged buttons infer `neutral`; `data-sfx` only upgrades semantics.
- React bridge: the engine `bump()`s a version counter; components subscribe via the hooks in `src/hooks/use-engine.ts` (signature selectors for cheap components, full-version for detail panels). `App.tsx` itself does not subscribe globally.
- `src/components/BottomBar.tsx` — the gameplay build UI (a **bottom bar**, W&R-inspired, replaced the old left `BuildMenu`): a 3-tier drill-down (category → sub-category → building grid from config's `CATEGORIES`/`SUBCATEGORIES`), docked placement-mode toggles, and a right-end **demolish + hide/pin** cluster (pinned by default; retracts to a sliver you hover to peek — the retract uses an inline `style` transform, not a Tailwind arbitrary `calc()` class, which silently emits nothing). The toggles set the default `BuildPolicy` (`{autoBuy, currency, instant, plan}`) stamped onto each new site; per-site editing happens on the `SidePanel` detail panel. Checkbox controls are gone — the reusable pressed `ToggleButton` (`menu/controls.tsx`, `aria-pressed`+`data-sfx="toggle"`) is the on/off idiom everywhere.
- `src/components/ui/` and `src/hooks/use-mobile.ts` are vendored shadcn/ui — excluded from linting, don't hand-edit. Menu screens live in `src/components/menu/` (hand-rolled Tailwind on the shared `MenuShell`; inline `TwoStepButton` confirms, no nested modals).

## Rules

- **UI never re-computes simulation math.** Panels display engine APIs (which forward to `World`) — `productionRates()`, `importPriceOf()`, `sellableStock()` — and mutate via engine methods (`toggleStaffPriority()`), never by writing engine fields. This is what keeps display and simulation from diverging.
- **The economy is bulk/continuous; wholeness is an edge property, not a representation.** `b.stock[r]` is a float by design (production/wear/consumption are all fractional rates) and that is correct — every resource is bulk (tonnage), none discrete. "Whole units" matter only at three edges: trade, contracts, and display. The border already trades whole units (`sell`/`buy`/auto-trade floor); the **display** edge is the `src/game/format.ts` vocabulary — `fmtQty` (whole amount), `fmtLevel` (precise bin gauge — the one place a fraction is shown, on purpose), `fmtRate` (per-day flow), `fmtOwed` (shortfall — ceils, the mirror of `fmtQty`'s floor), `fmtMoney`, `fmtPct`. Never format a player-facing quantity with ad-hoc `.toFixed`/`Math.floor` (that scatter is what leaked the `42.14 coal` float tail); `ui-guards.test.ts` fails the build on a raw quantity beside a resource name in an engine event. A genuinely discrete good (whole-unit inventory, discrete failure) would be a localized `ResourceDef.kind: 'discrete'` + a banking accumulator for that one resource — deliberately **not** built (no uniform flag while every good is bulk).
- **One owner for persistent UI surfaces.** Every right-side view is a `PanelMode` owned by `App` (exclusive by construction). Never give a component its own open/close state for a persistent surface — that's how the stockpiles popover ended up overlaying the Five-Year Plan.
- **No emoji; icons come from `src/ui/icons.ts`.** One Lucide-backed registry renders as SVG (`<GameIcon>`) and on canvas (`drawIcon`). config/engine reference icons by name string; `ui-guards.test.ts` fails the build on unknown names, emoji in first-party sources, or invalid Tailwind color-opacity steps (e.g. `bg-red-950/97` silently emits no CSS).
- **Weather is engine state.** `engine.weather` / `engine.forecast()` are the only sources of truth — never derive weather from `season()` or the calendar in UI or render code (heating is temperature-driven via `heatingRequired()`, river ice follows `weather.riverFrozen`). Gameplay multipliers live in config's `WEATHER` table; the timeline draws from its own decorrelated RNG stream so it never perturbs economy randomness.
- **Money is foreign currency only.** Nothing domestic costs rubles or dollars *for free labor*: buildings and roads cost materials + builder labor (roads/bridges are real per-tile construction sites — gravel or planks+steel trucked in, undrivable until complete, `becomesRoad` dissolves the site into a road tile). Money enters at the border (exports, contracts, Moscow's objective rewards) and leaves at the border (imports, contract fines). Construction policy is **per-site** — the bottom-bar toggles stamp a default `BuildPolicy` onto each new site, editable afterward on its `SidePanel` (`setSiteImport`/`setSiteForeignLabor`/`finishSiteInstant`/`commenceSite`). Three domestic ₽/$ sinks, all border-priced: **instant build/finish** ($, `instantCost`/`instantFinishCost` — a Western prefab at placement, or completing an existing site's *remaining* work); **auto-buy** (₽ East **or** $ West, `autoBuyImportCost(defId,x,y,currency)`/`autoBuyRemainingCost` — pays a site's import bill, delivered as **bonded virtual imports** earmarked via a `{from: customsId, bonded: true}` demand that never touches customs stock — cap-exempt, leak-proof); and **foreign construction labor** (₽/builder-day, `BALANCE.foreignLaborPerDay`) — `construction()` is **two-phase**: citizens build every ready site free, then paid foreign builders top up only sites whose per-site `foreignLabor` permits it (default = the global `foreignLaborEnabled` menu toggle), affordability-capped so ₽ never goes negative, surfaced on `tradeLedger.*.foreignLabor` (the single-pass progress step keeps it byte-identical to the old lump when every site allows foreign labor). **Planning mode**: a `plan`-placed site is `paused` (orders nothing, no builders) until `commenceSite()`/`commenceAllPlanned()`, which charges any deferred auto-buy at commence. Machinery is the physical face of that dependency: industry needs it to build AND to run (`wear` drains per-building spare bins daily; a dry bin means `buildingWorn()` and ×`wornEffMult` output, never a stall) — imported at first, produced domestically once a Machine Works closes the loop. `campaign-pacing.test.ts` is the balance tripwire (a pinned 3-year build order in `campaign.ts` asserting solvency + the machinery/foreign-labor arc): if a deliberate rebalance moves the curve, re-derive the trajectory with a scratch runner and re-pin — never loosen thresholds blindly.
- **Roads are the fast freight network, not a hard gate.** Trucks prefer roads but may drive **off-road** across any non-water, non-foreign, unoccupied land tile at `BALANCE.offRoadStepCost`× the per-tile time, so a building with no road still receives slow deliveries (dispatch in `logistics()` tries a road-only bounded search first, a weighted-land one second via `routeToSupply` — road-connected towns stay byte-identical; `floodTerrain` still backs the off-road refund). Water still needs bridges/ports/barges; off-road is land-only. `b.connected` = a finite-cost land-or-road path reaches the freight network — **depots and ports** both seed it (a port is where barges land goods, and an island with no connected building owns no lorries, so nothing could ever be unloaded there) — and it gates staffing/builders/the fleet; `b.roadConnected` is the stricter road-only state driving the "off-road — slow; lay a road" advisory. Bulldozing an unfinished site returns its **already-delivered** `stock` to storage by truck (`refundSiteStock`, off-road capable) — never let it vanish; the in-flight turn-back conserves cargo still on the road, the two are disjoint.
- **The fleet is made of vehicles, not shipments.** A `Vehicle` is a persistent machine owned by a garage (Construction Office / Motor Depot): `syncFleet()` builds one per `trucksFrom()` when the garage is staffed and retires it with the garage, `logistics()` **assigns jobs to idle lorries** instead of spawning trucks, and a lorry parks where it finished and takes its next job from there. Every vehicle carries its own fuel — there is no pooled fleet tank and no per-day fleet levy; fuel leaves a building's bin exactly once, when a lorry pumps it (`refuelVehicles()`), and `BALANCE.vehicleFuelPerTile` burns per road-tile-equivalent so an off-road leg costs `offRoadStepCost`× the fuel as well as the time. **A lorry never accepts a job it cannot finish** (`pickVehicleFor` checks tank vs. run + `vehicleReserveTiles`), which is why running dry is a dispatch-time refusal, not a stranding; the fleet grounds itself visibly instead (`fleetStatus().grounded`) and `checkEmergencyFuelAutoBuy()` — called at the very *top* of `logistics()`, before the fleet is counted — buys the bootstrap ration at the border. A vehicle is always parked at a building (`atId`) or driving one leg that ends at one (`legTo`; `destId` stays the job's destination across both legs), and nothing mutates until a route is found, so `destId` and `points` cannot disagree. The loaded leg is routed at dispatch and carried on the lorry (`pendingPath`) so the supplier's ranked access-tile rules decide the driven path and a delivery costs one search, not two. Garage lorry counts are **vehicles**: the pre-fleet figures counted concurrent outbound shipments (a returning truck had already freed its slot), which is why they doubled when the fleet became physical.
- **Delivery is ranked by downtime prevented, never by a priority table.** There is deliberately no `prio` band list: `dispatchScore()` derives rank from the sim — `coverDaysOf()` (stock ÷ drain = days of operation left) against delivery ETA, valued by `avertedDaysOf()` (downtime this load prevents) × `consequenceWeightOf()` ÷ round-trip. A bin that was never going to run dry averts ~0 and scores ~0 however empty or near it is; that non-linearity is what lets round-trip cost divide the score **unconditionally**, with no lifeline carve-out. Four consequences are load-bearing, each learned by measurement — do not "simplify" them back:
  - **Drain is `nominalInputRate()` (what a building WANTS), never `productionRates()` (what it gets).** Actual flow throttles to zero when a bin runs dry (`inputFactor`/`coalFactor`), so urgency-from-flow means a starved building reports needing nothing and is never resupplied. Same trap in `poweredDependents()`: it measures the grid by power *demand*, because a dark plant produces nothing and would otherwise look inconsequential exactly when it matters most.
  - **Nothing escalates inside construction.** A site consumes nothing, so its score is flat (× tier × the category dial) and ties fall back to commissioning order, which finishes sites one at a time. Both obvious escalations are rich-get-richer and measurably starve NEW sites — ranking by nearness-to-completion *or* by days-blocked left the campaign's steel mill permanently unbuilt with steel output at zero. Balance construction against industry with `consequenceConstruction`, which scales every site equally.
  - **Two passes, and the second is the safety valve.** Pass 1 is marginal greedy over positive-score demands, re-scoring the served building after each dispatch — that alone makes load spread across rival destinations, so there are no reserved slices and no fair-share quotas. Pass 2 then runs *everything that prevents no downtime* (overflow, export staging, comfortable top-ups, stocking a shop with no citizens yet) on leftover trucks. Scarcity is therefore the only regime where ranking bites.
  - **Bound routing attempts, not the candidate list.** Slicing the ranked pool let a few high-scoring unservable demands crowd real needs out of the window entirely. Each pass is capped at `logisticsCandidateFactor` attempts per free lorry, and pass 2 gets **its own** allowance off the lorries pass 1 left: one shared counter starves the border exactly on the busy days worth exporting from.
  The player's whole control surface is `logisticsCategoryWeights` (four dials, `setLogisticsCategoryWeight()`); they scale consequence and are allowed to reorder categories, but no setting can conjure value — zero-averted work can never preempt a real need. `logisticsPriorityPreview()` is the engine-owned view and returns the reason sentence the panel shows; a dispatcher the player can't interrogate is one they can't trust.
- **Trade crosses the border physically.** One map edge per seed is the national border (`tile.foreign`, `engine.borderEdge`); foreign soil is unbuildable and customs houses must stand on it, each clearing a staffed daily throughput (`BALANCE.customsThroughputPerDay × eff`). Auto-trade policy, the daily `tradeLedger` and `contracts` are engine state mutated only via engine methods (`setAutoTradeRule()`, `acceptContract()`, …); auto-exports are truck-staged to customs stock before sale, and both sale paths pay through `exportPayout()` so contract deliveries can't be missed. Contract offers draw from a stateless per-month rng stream — never from the economy stream.
- **Saves must round-trip bit-exact.** `save-roundtrip.test.ts` serializes, reloads, then advances both engines 90 days and compares everything — a new mutable engine field must be added to `serialize()`/`fromSave()` (and hydrates over a default) or that test is the tripwire that catches you.
- **The web build is primary** — the browser workflow must never break; desktop is a Tauri shell around the same dist. `src/platform/` is the ONLY layer that touches `@tauri-apps` APIs (always via `isTauri()`-gated dynamic imports — the web bundle stays Tauri-free) or raw `localStorage`: all persistence goes through `storage()` from `src/platform/storage.ts` (browser = localStorage, desktop = real files in `%APPDATA%\com.noahsabaj.redrepublic\` via an in-memory cache with async write-behind — `save-roundtrip`-style sync callers keep working, disk failures surface on the error bus). Any desktop quit path must call `quitApp()` (flushes pending writes, then destroys the window) — never `getCurrentWindow().close()`, which loops the close-confirm. The user-facing exits — main-menu **Exit Game** and the pause **Exit → (Main Menu / Desktop)** chooser — are desktop-only (gated on `isTauri()` via an optional prop off App's one `isDesktop` const, never an inline `isTauri()` in render) and route desktop-exit through `quitApp()`; web keeps a single Exit-to-Main-Menu. **Window mode** (`settings.windowMode`: windowed / borderless / fullscreen) is the third such surface and has exactly one owner: `desktop.ts` subscribes to the settings store and applies it — the Options control and F11 only *write* the setting, so the panel and the hotkey cannot disagree. Borderless is `setDecorations(false)` + `maximize()`, letting the OS find the work area (taskbar stays reachable) instead of doing monitor math; `tauri.conf` boots `fullscreen: true` so the default never visibly reframes, and `resetSettings()` deliberately carries `windowMode` over because it is a display choice, not a game preference. `tauri-plugin-window-state` runs with `SIZE|POSITION|MAXIMIZED` only — it does **not** restore fullscreen/decorations, so it cannot fight the mode, and it is already what remembers windowed geometry. `src-tauri/` is Rust, not covered by `bun run check`; capabilities follow least privilege. The app version lives in `package.json` only (`tauri.conf.json` points at it). **The Linux store listing is metadata, not code**: `bundle.license`/`licenseFile`/`homepage`/`copyright` fill the deb/rpm tags, but RPM's `Vendor` is not reachable from Tauri config — what Discover and GNOME Software actually render as name/developer/license is the AppStream metainfo at `src-tauri/metainfo/`, shipped via `bundle.linux.{deb,rpm}.files` and validated with `appstreamcli validate`. Its `<launchable>` must track the `.desktop` filename the bundler derives from `productName`, and it deliberately carries no `<releases>` block (that would be a second place to bump the version). **On NVIDIA's proprietary driver the Linux rendering fix is display-server-specific**; `lib.rs` applies it before GTK init, gated on `/dev/nvidiactl` so nouveau/Mesa/AMD/Intel keep their defaults. On **Wayland the DMA-BUF renderer must stay ON** — it is what gives the canvas GPU compositing, and without it every frame moves the whole canvas to screen on the CPU (~51 ms for a 4800×2512 canvas = 12.9 fps, where Chrome runs the same build at 60). The renderer is not the bug: the dmabuf buffer allocates fine and then the compositor kills the client over NVIDIA's explicit sync (`wp_linux_drm_syncobj_surface_v1: explicit sync is used, but no acquire point is set`), so `lib.rs` sets `__NV_DISABLE_EXPLICIT_SYNC=1` — 12.9 fps → 60. The **accepted** cost is a WebKitWebProcess segfault inside `libnvidia-eglcore` tearing down Skia's GL context **at quit** (4/4 runs, vs 0/4 with the renderer off): saves flush before the window is destroyed and gameplay survives resizes at a sustained 60 fps, so it costs a coredump on exit and nothing else. On **X11/XWayland** a different failure has no known workaround (`Failed to create GBM buffer: Invalid argument`, nothing renders at all), so there `WEBKIT_DISABLE_DMABUF_RENDERER=1` still applies — `prefers_wayland()` treats an explicit `GDK_BACKEND` as outranking the session vars, and an explicit env value always wins per variable. Never "fix" Linux framerate by lowering `dprCap`: measured **worse** (84 ms vs 69 ms), because a canvas backing that mismatches the device pixel grid adds a filtered upscale. Release = bump version → tag `vX.Y.Z` → push → CI drafts a GitHub Release with installers → wait for the run, verify the Windows assets, then **publish without pausing** (`gh release edit vX.Y.Z --draft=false --latest`; user directive: "always ship") — publishing arms the auto-updater for every installed copy.
- Every bug fix lands with a regression test in `src/game/__tests__/`. Engine tests build worlds with `helpers.ts` (`makeEngine()` = flat map, no starting base, **no border**, **calm weather** — pass `weather:` to script conditions; `flatBorderMap()` opts into border rules; real-map behavior needs `new GameEngine` directly; `flatMap(w, h)` takes dimensions). Remember `pop` clamps to housing capacity at day end — place beds before setting `pop`.
- **Canvas Dimension Re-Allocation Guard:** In HTML5 Canvas components (`GameCanvas.tsx`), assigning `canvas.width` or `canvas.height` (even to the same number) clears the drawing buffer and resets context properties. Always guard canvas backing assignments with an explicit equality check (`if (canvas.width !== nextW || canvas.height !== nextH || dpr !== nextDpr)`).
- **Offscreen Tilemap Caching:** Decouple static terrain rasterization (water, grass, rock, forest ground, grid lattice, farm fields, deposits, roads, and border lines) from dynamic entity rendering (`TilemapCache` in `tilemap-cache.ts`). Cull offscreen dynamic entities before depth sorting.
