# Red Republic

A planned-economy city builder. Rust, desktop-only. **The simulation is a library with no engine dependency**; the renderer and UI shell are a separate, later, evidence-based decision.

The 1.x build (TypeScript + React + canvas 2D) is **frozen at v1.10.0 and no longer lives in this repository.** It was moved out on 2026-07-30, when this build became the official one — on Noah's machine it is at `D:\archive`, together with the saved republics from the installed 1.x game. Git history still holds it, so `git log -- archive/` and `git show <rev>:archive/...` reach it from here without it sitting in the tree.

It is not a dependency, not a migration source and **not a spec** — it is a **balance and information-architecture reference**, worth reading for numbers that were already felt out and for how a panel was laid out. Port rules, never code. Nothing in it gets fixed, built, or released again. The bar this build is measured against is Workers & Resources: Soviet Republic, not v1.10.0; the file that said otherwise was deleted on 2026-07-28 and the goal explains why.

## The goal

**Red Republic is finished when a stranger could install it, play it, and nothing in it embarrasses you.** Decided 2026-07-28, because the work had been running plan to plan with no terminus and nothing in the repo named one — which meant there was no way to rank two pieces of unrelated work against each other. **Widened later the same day to the headline in full**: the three conditions under it excluded art, audio and fun by their own admission, and the ask is playable, shippable and enjoyable. The headline binds; the conditions serve it.

Three conditions, and all of them hold together:

1. **Nothing the simulation knows is invisible — an invariant, not a terminus.** Everything modelled is visible to the player, and controllable by them wherever it is a decision rather than a consequence. This was first written as closable only once the simulation stopped growing, and that reading made it **unreachable** the moment the parity roster below was adopted: a condition that closes only when the work stops is a condition that never closes. It is now a **per-change rule** — every new simulation fact ships with its UI in the same commit — which is always true rather than eventually true, and lets the simulation grow without ever unclosing it. **Enforced in code rather than described here**: the exposure guard fails the build when a public view on the sim is read by no shell code. It is also what reversed the order below, since a rule about shipping UI alongside simulation cannot be obeyed before a shell exists.
2. **Feature parity with Workers & Resources: Soviet Republic.** The roster is named explicitly below, because "W&R" is eight years of development and is not a stopping rule. **This replaces the 1.x port checklist and `crates/sim/PORTING.md` is deleted** — that file measured the work against what a dead prototype happened to do, which is the wrong bar for a game whose stated purpose is to beat a different one, and it read as a standing obligation list. The 1.x build stays as a **balance reference** and is no longer a spec.
3. **A republic survives a decade without an artificial wall.** Four climates, one fixed seed each, ten simulated years through `src/bin/trajectory.rs` — and every wall it hits is a design consequence rather than a bug, a missing system or a balance hole. **Measured 2026-07-28, and the decade stands:** a founded republic draws 2,160 t/yr from a 1,305,674 t coal body — 1.65% in ten years, and **594 years to exhaustion**. So the bar never reaches depletion, which is exactly what this caveat suspected. **This changes nothing, and the caveat was chasing a problem that did not exist**: the mining town is already proved by `citizen::tests::a_mining_town_dies_when_its_work_does`, which exhausts a deposit outright and asserts the town is left with no work in reach. It was never waiting on a trajectory. Recorded because the mistake is instructive — a scenario named in prose without naming its test reads as an obligation, and gets re-proposed as work until somebody greps.

**Held to the standard of a public release, and the artifact is now a Windows installer.** No placeholder strings, no debug UI left in, no crash on a GPU nobody here owns, settings that work, a game that explains itself to someone who was not present while it was built — and it installs on a clean machine with no Rust, no Godot and no Steam. **The standard and the shipping are still separate things**: building an installer is part of finishing; putting it in front of anyone is not, and nothing gets distributed without Noah saying so in the conversation where it happens. **Half of it now has an automatic check, and the half that matters most still does not.** The installer is built by `tools/package.ps1` and CI's `package` job exports it, installs it silently on a Windows runner, runs the *installed* game's `--check`, and uninstalls it again — so "it installs on a clean machine with no Rust, no Godot and no Steam" is a tested claim rather than a sentence, and a runner is a better witness for it than this desktop, which has all three sitting where an export could quietly depend on them. **What no check will ever cover is the first clause** — no placeholder strings, nothing left in, nothing embarrassing. That is still attention alone, and it is still the condition that will drift.

**Real-time is the thesis.** One real second is one in-game second at speed 1, the hook singled out as the thing no comparable game does. Done requires it to be genuinely worth playing at rather than merely present and correct: vehicles visibly crossing ground, holding frame rate. That is a real constraint on the renderer, and it is why the physical fleet went ahead of the shell.

**Existence is the difficulty.** There are no difficulty levels and there will not be — the land is the difficulty. Founding already varies land quality genuinely, a taiga posting measurably costs more to run than a plains one, and choosing a hard posting is a choice made inside the fiction rather than in a settings menu; a multiplier bolted on beside it would quietly say the land choice never meant anything. Underneath is a balance thesis, in the words it was decided in: *"Socialist Republics are not a walk in the park, those are difficult projects."* The game is uniformly hard because its subject is hard, and **no tuning pass may soften a start to make it comfortable.**

**Order: the shell comes first now, and the simulation grows underneath it.** This reverses what was written on 2026-07-27, and condition 1 is the reason rather than a change of mind — a rule that every simulation fact ships with its UI in the same commit cannot be obeyed while there is no UI. The old order existed to stop a shell chasing a moving simulation, and the Godot decision it gated on **was already falsified by throwaway probes**: a real heightmap, a real building MultiMesh and a dense `Control` sweep, measured once and deleted. A probe is not a shell, and the gate demanded proof of the *decision*, which is what it got. With parity adopted the simulation will be moving for a long time, so "wait until it stops" is no longer an order — it is a refusal to start.

**What the goal does not cover**, said plainly so silence is not mistaken for coverage. It still has **no criterion for whether the game is fun**: every condition is structural, a republic can clear all three and be tedious, and neither the trajectory runner nor any test here can say so. Three things are aimed at that and none of them is a proof — designing against W&R's named failures, a friction report out of the trajectory runner, and Noah playing it. **The last is the only verdict.** Art and audio are now in scope where they were previously excluded; the look is chosen from mockups rather than argued in prose, and music is the one thing here nobody in this repo can judge but him.

### The parity roster — condition 2's stopping rule

Named explicitly, because "parity with W&R" is not a bar anyone can hold you to and this has to be one. When every row here is built and visible, condition 2 is closed.

Terrain and borders · construction (offices, crews, machinery, construction vehicles) · production chains and an expanded resource set · storage (open, warehouse, aggregate, tank, silo) · distribution offices · road freight · rail · water transport · air · cableways and conveyors · pipelines (oil, heat) · passenger transport (bus, tram, trolleybus, metro, rail) · citizens with needs, health, education, loyalty and life stages · services (shops, kindergarten, school, university, hospital, pharmacy, fire, police, prison, court, sport, culture, cinema, broadcast, cemetery) · waste management · pollution · power (plants, lines, substations) · heat (plants, pipes) · seasons and snow clearance · the two-bloc economy, trade, loans, contracts and customs · tourism · vehicle depots, fuel and maintenance.

**Every row above is now built**, and the bold that used to mark the recent arrivals has been dropped rather than extended — a roster where everything is emphasised emphasises nothing. What that does **not** mean is that condition 2 is closed: the condition is built *and visible*, the exposure guard only checks that a view is read somewhere, and "read somewhere" is a long way from "read well". Depth is the honest gap — the chains are three deep where W&R's are five or six, and the services are one building per need rather than a ladder. Widening them is data rather than design, which is exactly why it should not be mistaken for done.

**Deliberately not in it**, so silence is not read as coverage: water and sewage (deferred by decision, below), land purchase (**W&R has none** — the map inside the border is yours from day one), any objective or goal-loop system, and any novel mechanic. **New angles are Noah's to invent.** Parity is the floor I build; inventing past it is not mine to do unasked.

## The finishing decisions

Taken 2026-07-28 in the interview that set the scope above. Everything here was undecided or wrong before it.

- **The border is the whole perimeter, and it has two sides. Built.** `Frontier` replaces `BorderEdge`, which named one edge as foreign and said nothing about the other three — so a republic had a single frontier and three impassable nothings. The perimeter is one parameter in `0.0..4.0`, partitioned into arcs held by the **Western Alliance** or the **Eastern Bloc**, with four posts placed at worldgen on the republic's own ground. **You do not build a crossing; you build road out to one.** Everything inside the border is yours on day one.

  **Trade is geographic, and that is the whole point.** A customs house clears *only* for the bloc whose post it stands at, so earning dollars means hauling to a Western post — and if the only Western post is across the map, that is what a dollar costs. The trajectory runner proved it in one run: told to sell coal east from a republic whose crossing is Western, it earned **zero for two years**. It now reads the bloc off its own crossing, which is what a competent player would do.

  **Loans are built, and a test rewrote the mechanic within a minute of it existing.** Three tiers per bloc, simple interest locked at taking, one advance per bloc at a time, and a daily sweep that defaults an overdue one. The first version's only penalties were a fine and soured relations — and `Treasury::debit` deliberately refuses to go negative, because a republic does not run an overdraft it never agreed to, so **a fine on an empty purse takes nothing and defaulting while broke was free**: borrow, spend it, default, borrow again. The fix is that a defaulted-on bloc **never lends again**, which is a consequence that does not need money to bite — the right shape for a penalty aimed at a republic that has none.

  **Refuelling away from home is built, and `GasStation` finally does something.** A pump within `REFUEL_RANGE` of where a leg ended tops a vehicle up, and dispatch counts a pump at either end of a haul when it prices the round trip. **The rule itself does not bend** — a vehicle still never accepts a job it cannot finish — but a filling point changes what finishing costs, which is what makes this a *range* mechanic rather than a safety one. It is a place, not a fuel pool: it must be built, staffed, stocked, and near you.

- **Construction Offices employ the builders and own the machinery, and they run crew buses. Built.** Not local hire: an office's workers commute to the office like any other workplace, and the office shuttles them out to its sites. That is a second physical transport hop, and it is deliberate — it means a remote site is expensive in the same currency everything else in this game is expensive in, which is vehicles, roads and time.

  **What that replaced was freight-before-lorries, one layer up.** Every office in the republic pooled its staff into a number of builder-days, and that number was spent on whatever site was next in the queue however far away it stood — a crew never travelled, and a site four kilometres out cost exactly what a site next door cost. A `crews::Party` is a gang that is *somewhere*: riding a bus, standing on a site, or standing beside a finished one waiting to be fetched, never two of those at once. `a_site_further_out_takes_longer_to_start` is the acceptance test and `nobody_is_in_two_places_at_once` is the invariant.

  **An office cannot be pulled down with its crews out, and neither can a site with a gang on it.** Refusals rather than tidying-up afterwards, because "the office is ten people short and nothing says why" is not a state worth being able to represent. `RecallCrew` is the way through, and it is the player's call rather than the simulation's: deciding when a plan has gone wrong is not a judgment to take off them.

  **Two bugs of one shape, both found by measurement and neither by reasoning.** A gang waiting for a lift stays waiting until the bus *arrives*, and a gang riding toward a site is not yet *working* it — so the first version sent a second bus after the same ten people every tick (which cost a republic one of its two buses permanently: the second arrived to find nobody there and sat in the field holding a job it could never finish), and it sent twenty builders to a road that can absorb ten. **A journey is a commitment, and a dispatcher that only reads arrivals will make it twice.** Freight learned this once already and calls it `Booked`.

  **The bogging roll for a bus is real and very long odds.** Measured before it was declared: 130 ferries over 600 simulated days, median journey two kilometres, and exactly one casualty — in taiga. An empty bus is the second most capable thing the republic owns, so the write-set guard's fixture has to saturate the ground deliberately to reach the roll at all. That is the honest version of "reachable but rare", and it is written down because the alternative was quietly dropping a declaration nobody could exercise.

- **No instant build. Ever.** Paying hard currency to make a construction site vanish is the *"click a button and it goes away"* shape this build exists to refuse, and it is the one 1.x rule explicitly not carried. Anything sourced **inside** the republic costs labour and materials and no money at all. Foreign labour is paid in its own bloc's currency, foreign materials likewise — Bloc in roubles, Western in dollars. Auto-import can be set globally or per site and lands the goods **at a chosen crossing**, where your own lorries collect them. Foreign crews arrive at that crossing too and have to be carried to the site.

  **Foreign labour is built.** You hire builders from a bloc *to a Construction Office*; they cost a placement fee now and a wage every day thereafter, both in that bloc's own currency, which is the whole trade against training your own — domestic labour costs the republic no money at all. **They arrive at a frontier post rather than in the yard**, which needed no new mechanism: a gang with nowhere to be and no lift is exactly what already asks an office for a bus. Until that bus reaches them they are not on the office's books, so they cannot be posted and cannot be counted twice.

  **An unpaid wage costs the worker, not a fine.** The lesson loans taught, applied before it could be relearned: `Treasury::debit` refuses to go negative, so a penalty denominated in money takes nothing from a republic that has none — which is precisely the state an unpaid wage bill describes. As many as the money did not cover go home, and the republic is left with the half-built site it hired them for.

  **Auto-import is built too.** A `BuildPolicy` names the post a site buys through — globally, with per-site overrides, and an override may say *off* while the republic imports, which is why it is an `Option<Option<CrossingId>>` and not a crossing. Choosing a post chooses a currency and a distance at the same time, which is the same geography the trade rules already answer to. Nothing is reserved: the goods land in the post's yard and the ordinary freight ranking takes them from there.

  **The Directorate buys a site's bill once, and that rule had to be discovered.** The first version chased the *shortfall*, which is not the site's property — the goods land in a border yard and the republic's own freight decides where they go. Measured: a six-tonne bill bought **forty-eight tonnes** of machinery, because a Construction Office about to run dry outranks a foundation and the lorries kept taking it there. A per-site purchase ledger fixes it, and the failure mode it chooses is deliberate: **a stalled site rather than an emptied purse**, because a site standing still is on the screen and hard currency draining into a border post is not.

- **Happiness drives migration, and the population is alive. Built.** `Building::provisioned` and `heated` had been computed every tick with nothing reading them; contentment is what they were waiting for. A republic that fails its people loses them, and one that serves them attracts more — the only thing in this design that pushes back on the player. Alongside it: births, ageing and death, and immigrants who **physically arrive** at a frontier post and have to be carried to housing.

  **Contentment is a breakdown, not a score, and that is the whole design.** Six named components — provisions, warmth, health, culture, schooling, work — each `0.0..=1.0`, weighted, with `Contentment::worst` naming the one costing most. "Your people are at 61%" is not something a player can act on and "fed, warm, no doctor, no work" is. Warmth is `1.0` on a warm day rather than a failure nobody was being asked for, and schooling is `1.0` in a block with no children — both for the same reason the boilers read today's temperature: a republic should not be marked down for a demand that does not exist.

  **A settler is fetched by a coach, and the mechanic has a bound that fires.** A group stands at a post; a `Coach` from a Bus Depot drives out, picks them up, carries them to housing with room, and sets them down as citizens. `Role::Passenger` is its own pool so a republic never stops building because its buses were fetching immigrants. After `migration::PATIENCE` — ninety days — a group nobody came for **goes home**, which is what stops a republic with no transport hoarding an unbounded crowd at its border. That is not hypothetical: **the founding has no bus depot, so a default republic turns everyone away.** Measured over three years on the standard seed: 0 settled, 68 turned back. That is a consequence and it is on the screen, not a bug — the player's first real growth decision is a bus depot, and softening it would be exactly the tuning the goal forbids.

  **Emigration deliberately has no journey.** Somebody who has decided to go does not need the republic's transport, and making them queue for a coach out would mean a failing republic *retained* people by failing harder.

- **Education is what makes the next generation employable, and it is a real cost.** `BuildingDef::schooling` is authored on every row — the least a job needs — and the labour pass enforces it exactly as it enforces reach: a job nobody is qualified for goes unfilled however many people are out of work. A Ten-Year School turns children into `Schooled` adults; a Polytechnic Institute turns those into `Graduate`s, and a **refinery and a machine works cannot open without them**.

  **The chain is deliberately not circular**: a university's own staff need only to be schooled, so a republic can always open one with the hand Moscow sent. And **a student is a working-age adult who is not working** — three years of hands the republic does without — which is what makes a university a trade rather than a free upgrade.

  **An adult conjured into the republic arrives schooled and a newborn does not**, by construction in `Population::spawn_citizen`. The only two ways somebody appears at an adult age are the founding hand and immigration, and both were taught somewhere else. A person who grows up *inside* the republic never comes through that path — they are born at nought and age — so what they know is whatever the republic gave them, which is the entire point of the attribute.

- **Power and heat became networks, and that was the last free thing in the simulation. Built.** A plant anywhere on the map used to light every building on it, and a boiler anywhere warmed every block — both were quantities with no geography, which is exactly the shape freight had before lorries and construction had before crews. `utility.rs` is what makes them physical: a span is **ordered, materialled, built by the same crew in the same commissioning queue, and carries nothing until it is finished**, precisely as a road is.

  **One module for two networks, because they are the same shape** — linear, built the same way, connecting producers to consumers — and they differ only in cost, reach and loss. What they do *not* share is a network: `Utility` is part of a line's identity, so a pipe never carries electricity. The node pool had to be split by kind to make that true; `the_two_networks_never_touch` is the test that caught it merging a pylon with a manhole.

  **A power line and a heat main are deliberately different animals.** Power is cheap per kilometre, reaches 250 m sideways and loses 1.2% a kilometre, so a republic strings it across the map. Heat is dear, reaches 110 m, and leaks 7% a kilometre — which is why district heating is a town-scale thing in every country that has it, and why a remote camp wants its own boiler rather than a pipe from the city.

  **Two hops on the power side, one on the heat side.** A consumer plugs into a **Transformer Station** within `TRANSFORMER_RANGE`, and the station plugs into the line; a pylon strung past a factory is not what runs it. Heat has no equivalent because a main really does run to the door.

  **Connection is stored, not searched.** Testing every building against every span on every tick is `buildings × lines` distance tests 1,440 times a day, so a building is attached once — at placement, or when a span opens near it — and the attachment is a node in a union-find. Two grids that later meet merge in one union rather than by rewiring anybody. Same discipline as the traversal lattice: derive at the event that invalidates it, not per tick.

  **The first bug this produced was found by measurement and would never have been found by reading.** A boiler throttled to demand and *then* had the pipe loss taken out of what it made, so it was short by exactly the loss every time: the founding's third block went cold in January with the boiler running at 71% and coal in the bunker. It now throttles to demand **at the far end of the main**.

  **Moscow sends a town that is wired**, and the grid goes in with the plant and the boiler rather than after the shops — because the order things are founded in is the staffing priority, and transformer stations placed at the tail stood unmanned, which took the power out of the boiler, which took the heat out of the housing. `SETTLERS` rose from 130 to 139 to man them, and to 143 when the Council Depot took on snow ploughs. That is the customs-house lesson recurring exactly, and `the_founding_hand_can_staff_itself` caught it again.

- **Rubbish is a resource, and pollution is a field. Both built.** `Resource::Waste` accumulates in the bins of the buildings that make it — per resident for housing, per unit of activity for everything else — and it has to be **driven** to a Landfill or a Refuse Incinerator. Neither needed a new mechanism: a landfill *consumes* waste, so it is a consignee the existing freight ranking already understands, and a republic with nowhere to take its rubbish simply watches it pile up. Measured on the standard seed: **686 t after three years, and 35% smoke over the town**, with no landfill in the founding. Both are consequences on the screen and neither is softened.

  Pollution rides the 100 m traversal lattice beside wear, for the same reason: what varies at ten metres is where a building can stand, and what varies at a hundred is where the smoke goes. It costs crop yield at the farm that stands in it and contentment at the block that lives in it, and it is read through the **pollution overlay**, because smoke is invisible on the ground by design.

  **Dispersal is proportional rather than a flat subtraction, and that took a measurement.** A flat rate makes the steady state a step function — a source under the rate settles at clean and one over it settles at filthy, with nothing between — so a brickworks and a steel works would look identical. Decaying by a share gives every source its own level, which is the whole point of authoring different figures. A floor is what lets a valley come genuinely clean rather than approaching it for ever.

  **Contentment gained a seventh component, `Cleanliness`**, covering both — a resident cannot tell a full bin from a works upwind, both are the player's to fix, and splitting them would lengthen the panel without sharpening a decision. Adding it also broke two things sized to the roster of the day: a HUD table with exactly eighteen rows, and a shell view with a literal `[0.0; 6]` that `zip` silently truncated. **Both symptoms were a row quietly missing**, which is why the sizes are now derived from `Contentment::NAMES` rather than typed.

- **Bridges are built, and the rule they enforce was not being enforced at all.** `going_on(Surface::Water)` is `f64::INFINITY` and the design recorded water as impassable — but **nothing checked what a road ran over**, only its two ends, so a gravel road could be laid straight across a river at the price of gravel and lorries drove it. `Grade::Bridge` is its own grade with steel, brick and gravel by the kilometre and 520 builder-days of it, it is the only grade that may span water, and `RoadError::NeedsABridge` is what a player is told otherwise. A river divides a republic until somebody pays for it. **Still to come**: water as a *medium* rather than only an obstacle — ports and barges, so the rivers are an asset.

- **Conveyors and pipelines are built, and they are the same machinery as the grid.** A belt and a pipe are ordered, materialled, built by the same crew in the same queue, and attached the same way — the only thing `utility.rs` needed was `carries` and `throughput` on the authored row. What a belt buys is a haul with **no lorry, no driver and no diesel**; what it costs is that it goes exactly where it was built and nowhere else. That is the trade against the fleet, stated plainly: a mine feeding one plant four hundred metres away wants a belt, and a mine feeding six things scattered over a valley wants lorries.

  The `belts` system runs **before dispatch**, because goods a belt has already moved are goods no lorry needs fetching for, and the other order would send one for a load that was about to arrive on its own. `no_resource_rides_two_networks` is the guard that keeps the two rosters disjoint — a resource both a belt and a pipe would take is a resource whose route depends on which pass looked first.

- **Storage stopped being a number, and two buildings turned out never to have worked.** `Resource::form` says what shape goods come in and `BuildingDef::admits` says what a place will take, so a tank holds liquids, a silo holds grain and cement, and a heap of gravel is a heap of gravel. Five forms, five stores, and not one list of resource ids inside a building. It governs **deliveries only** — a coal mine does not refuse its own coal and a house still fills a bin the refuse lorry empties — because what a player has a decision in is what somebody may *bring*. A site takes anything, or a tank could not accept the bricks it is made of.

  **The Gas Station, the Warehouse and the Council Depot had all been buildings nothing could ever deliver to.** `cover_days` reads `inputs` and a pump has none, so the resupply ranking had no reason to bring one a tonne of diesel ever: the founding hand-stocked forty tonnes and that was every litre a republic would see. `stores_to_order` is what makes a place a destination and all three had it false.

  **And chasing that found the bigger one: a standing order was a target with no floor.** A store holds goods it does not consume, which is exactly `serve`'s definition of a supplier — so freight brought the diesel in and the next pass took it straight back out, five deliveries over four days with the pump empty at the end of each. An office told to keep fifty tonnes was drained to **zero**. A distribution office, the whole point of M10's standing orders, was a lorry park. `what_a_store_is_told_to_keep_is_not_taken_out_again` is the guard.

- **The chains are three deep, and the luxuries are exports rather than wants.** Cement, concrete and prefab panels; bitumen, asphalt; chemicals, electronics; alcohol. The refinery is the only row with **two outputs**, and that is the mechanic: a barrel does not come apart into diesel alone, so a republic refining for fuel has bitumen whether it wanted any or not and it backs the refinery up until an asphalt plant exists. Paved road now wants asphalt, which is a **gate rather than a price rise** — gravel and brick are things a republic has on day one, so the best road in the game used to be available before anything had been built.

  **Alcohol and electronics are comforts: wanted at home *and* worth exporting, and the first version of this got it wrong.** They shipped as exports only, on the reasoning that making them ordinary wants would have dropped every standing republic's score the day the goods were invented — which was true, and was the wrong conclusion. The fix is to make them **additive**, not to keep them out of people's hands. `Contentment::comforts` is a **lift on top of the weighted needs** rather than a ninth component, so a republic that has never heard of vodka scores exactly what it scored before: measured on the plains trajectory, the `cont%` column is identical month for month across the change. Twelve points at full supply — enough to carry a republic just under `CONTENT_ATTRACTS` over it, nowhere near enough to rescue one that is cold.

  **Drink lifts a block and costs the people in it health**, which is the trade the player is being asked to weigh, and it is the reason `Building::drink` is carried apart from `Building::comforted`: a combined figure could not say how much of the lift was vodka rather than radios. Electronics have no such cost, authored by their absence — a television is not bad for you. `Contentment::worst` can never name a comfort, because "your people's biggest problem is no television" is not a thing to say to somebody whose estate is cold.

  **The general rule this is a case of**: a good that is *nice to have* belongs on top of the score, not inside it. A want is a way to fail; a comfort is a way to do better. Adding one as the other is how deepening an economy silently re-marks work the player already did.

- **Snow is a load on top of the ground, and a road is no longer weatherproof. Built.** `Ground::snow` had accumulated and melted since the ground model landed and **nothing outside `ground.rs` ever read it** — a republic under half a metre of snow drove at exactly its July pace. How much is lying is one figure for the republic; where it has been pushed aside is a *place*, so `Lattice::cleared` rides beside wear and pollution.

  **`Journey::speed_on` now divides a road leg by drag too**, and without that a plough would have had nothing to buy back. Mud and snow add rather than max, and wear relieves only the first: a packed track drains where a field does not and fills with snow exactly like the field beside it. Frozen ground is still hard however wet it is — the thaw is still the worst going of the year — but a frozen field under half a metre of snow is not a road.

  A plough is a Council Depot's, it never bogs (its capability is a recovery vehicle's, so declaring `Bog` would have been a declaration nothing could reach), and `clearing` is its own dispatcher because what it ranks is a stretch of buried road rather than a consignee. **Two things came out of measuring rather than reasoning**: the map-wide burial figure was useless — 94% through a winter with the ploughs working, because nobody ploughs a field — so `World::roads_unswept` is the number a player can act on; and the founding's diesel was **trapped**, because once the council depot declared a fuel appetite neither garage could supply the other and a republic with no refinery has no fuel supplier at all. Split 14/6, because Moscow fuels the vehicles it sends. What is left is a real gradient: taiga peaks at 81% unswept and plains at 53%.

- **Tourism is the republic itself as an export, and it is geographic. Built.** A party arrives at a post of its own bloc and spends that bloc's money, so which perimeter a republic can reach decides what its tourism is worth exactly as it decides what its coal is worth. They are **fetched**, out of the same coach pool as settlers, and `touring` runs after `settling` because that is where the judgement goes — somebody who wants to live here outranks somebody visiting. On the map they are drawn as one thing with settlers, because a crowd at a post waiting for a coach is the decision they share.

  What they pay for is culture within walking distance and air worth breathing, both read off machinery that already existed. `World::appeal_at` is a **placement query** — a player who cannot ask before they build has a building with a random yield. `beds` is its own field rather than a second meaning for `residents`: a hotel with residents would attract settlers to live in it and be marked down for having no school. The founding builds no hotel, so a default republic reports zeroes — the same shape as the missing bus depot and the missing landfill.

- **Water and sewage are deferred, and the reason is that the right answer is expensive.** It wants **real plumbing** — a pipe network peer to `RoadNetwork`, ordered and materialled and built. Hauling water will be possible and deliberately inefficient, so the pipes are the answer rather than a rule saying so. `Mineral::Groundwater` stays a peer field, which is what keeps this a deferral and not a retrofit.

- **The camera is free orbiting 3D with constrained tilt**, because real-time is the thesis and a lorry crossing a field has to be worth watching.

- **Art is a parametric kit of parts, plus hand-made landmarks.** Standardised Blender components — panel wall sections, window bands, roofs, stacks, gantries, silos — assembled from the `width` and `depth` already authored on `BuildingDef`. This is how Soviet construction actually worked, it keeps a hundred-plus roster visually coherent by construction rather than by discipline, and it makes a new building a data row that gets a model for free. Signature buildings are built by hand so the skyline has anchors. **Beautiful, not over the top**, and the look was chosen from mockups rather than from prose.

- **Audio is procedural now; the State Radio is plumbed and empty. Built.** Eight voices synthesised in `shell/audio.rs` — wind, rain, snow, machinery, engine, and three interface sounds — as 16-bit PCM the Godot side wraps in streams. **Nobody working on this repo but Noah can hear it**, so what the tests can hold is everything except taste: bit-identical generation, no clipping, a one-shot that ends at silence, and a loop that joins to itself.

  **The seam test taught the useful thing, and only by being sabotaged.** Removing the crossfade fails *two* of the five loops — wind and snow. Rain passes because dense white noise masks its own seam, and machinery and engine pass because every frequency in them completes a whole number of cycles across the loop. So the crossfade is not what keeps those two clean, and a frequency changed from 48 Hz to 47.5 Hz would break them in a way the seam test would report as a crossfade problem. `TONES` moves the frequencies out of the synthesis functions into authored data and `every_tone_in_a_loop_completes_whole_cycles` guards the class. The first attempt at sabotaging *that* picked 47 Hz, which is 141 cycles exactly and passed — an integer frequency over a whole-second loop always closes.

  **The beds follow state, never the calendar**, the same rule heating demand answers to. Machinery volume follows how much industry is actually running, so a republic whose works have stalled goes quiet — which is information arriving before the player opens a panel.

- **The game explains itself through a generated reference. Built.** No advisor, no scripted tutorial. `shell/reference.rs` generates the document from the authored tables — `BUILDINGS`, `Resource::ALL`, `GRADES`, `VEHICLES` — and `every_authored_row_reaches_the_reference` is what turns "cannot go stale" from an intention into something that fails the build. The hand-written part is deliberately bounded: a dozen paragraphs, each stating a **rule the design holds fixed** and never a quantity, because quantities come from the tables where they cannot drift.

  It renders as **one** `RichTextLabel` rather than a node per row, which is the measured virtualisation rule applied rather than worked around: a `Label` costs 165× more to build than to update, so several hundred entries would be a visible hitch every time the screen opened.

- **Founding, menus, settings and saves are built, and the shell is a screen machine now.** One scene, one `Republic`, screens as `CanvasLayer`s — because the founding screen's whole job is to hand a world to the thing that will play it, and a scene per screen would put the `Republic` in whichever one was loaded. Main menu, the two-beat founding shelf with real rasterised minimaps, a pause overlay, settings that persist, and a save/load list that shows every save **including the ones this build cannot read**, with the reason.

  **Settings are one table.** `settings_store.gd`'s `DEFAULTS` carries every setting's label, section, widget kind and default, and the screen is built from it — so a setting is a row of data rather than a row of data *and* a widget somewhere else. Defaults live there and nowhere else, which is what stops a reset button and a fresh install from disagreeing. There is no difficulty entry and there will not be: the land is the difficulty.

- **The command line grew `--screen` and `--check`, and both exist because of things that got past every number.** `--screen <name>` renders a named screen so every new panel can be *looked at*, which caught two layout bugs immediately — a `Panel` reports no minimum size from anchored children, so the founding cards came back zero pixels tall and the posting row drew straight over them, and the menu's button column ran off the right edge because `custom_minimum_size` is a floor rather than a width. Every node existed and every label had its text. `Style.card` is the fix for the class.

  `--check` founds a republic, writes a save, lists it, reads it back, compares, and quits. It is what CI runs, and it earned its place on its first run by failing with `os error 123`: the Rust side was being handed Godot's `user://` virtual path, which `std::fs` has never heard of.

**Versions are CalVer — `YYYY.M.PATCH`, decided 2026-07-30, and the first one is `2026.7.0`.** Bump the year and month at release time; the patch counts releases inside that month and returns to 0 when either changes. **There is exactly one version number in the repository**, `workspace.package.version` in the root `Cargo.toml`: the menu asks the loaded binary for it and `tools/package.ps1` reads it from `cargo metadata` for the installer and the executable's version resource, so a release is one edit.

Semver was the alternative and was rejected on what the number is *for*. Semver's promise is about an API and this ships no API; a date answers the question somebody holding an installer actually has, which is how current their build is. **The cost is real and is written down rather than discovered later: a version can now never announce that the game is finished.** That signal lives in the goal at the top of this file and its three conditions, which is the only thing that was ever going to test it. **This also retires a problem rather than solving it** — the 1.x build was `1.10.0`, so any 0.x number for the official build read as a downgrade; a date is not comparable to it at all. The 1.x install was removed from the machine the same day and the build moved to `D:\archive`.

## Commands

- `cargo test` — the gate. Run before committing.
- `cargo clippy --all-targets -- -D warnings` — lint.
- `cargo fmt` — format.
- **`godot --headless --path godot -- --check` — does the game actually load?** Rebuild the cdylib first (`cargo build -p red-republic-shell`) or it runs against the previous one. **`cargo test` does not parse GDScript**, and on 2026-07-29 that turned out to have hidden two breaks at once, both of which made the game refuse to start: `Overlays.Mode.SNOW` was referenced from three files including `overlays.gd` itself and the enum never got the variant, so every `.gd` failed to parse; and thirteen buildings had no row in `building_art.gd`, so the art guard asserted at load. Both had been on `main` since M11 and CI was green throughout. **The exposure guard could not see either** — it is a source scan, so it found the string it wanted in a file that cannot load and reported the view exposed. A scan over text cannot tell you the text is valid. CI now runs the import pass and the `--check` run as their own job, and the two steps are both necessary: the import catches the parse error and passes the missing art row. **`--check` also round-trips the settings store**, through a scratch file rather than the player's own `settings.cfg` — "settings that work" is a clause of the release standard, and rendering the screen only shows that the controls exist, which says nothing about whether a value written on one run is there on the next.

- **`pwsh tools/package.ps1` — build the Windows installer.** Release cdylib, generated export preset, Godot export, then Inno Setup, landing in `dist/`. It interrogates the export before wrapping it: the exported build is run and asked which artifact it is, and a reply other than `release` fails the packaging rather than shipping a development build that happens to live in `dist/`. Watched to fail against a debug export, which answers `development`. **This line used to report the resolved vsync project setting as well, and that was worse than useless** — `settings_store.gd` owns the shipped vsync default and `main.gd` applies it moments later, so the number named a value nothing downstream reads. A `.template_release` override in `project.godot` went the same way: it set something that `apply()` immediately overwrote. Both were caught by rendering the settings screen and reading what actually owns the setting, which is the second time a check in this repository has been aimed at a value nothing consumes. Needs Godot's export templates (a separate ~1.2 GB download from the editor) and Inno Setup 6; it names both in its error if they are missing. `-NoInstaller` stops after the export, `-SkipBuild` reuses the cdylib.
- **`python tools/build_icon.py` — regenerate the application icon.** Only when the design changes; `godot/icon.png` and `godot/icon.ico` are committed. Note `.gitignore` excludes `godot/*.png` for `--shot` frames and carries an explicit exception for the icon — without it an export silently falls back to Godot's own robot and every check in this repository still passes.

The 1.x build had its own toolchain (bun, vite, vitest) and was deliberately never wired into any of the above. It is out of the repository now, so there is nothing left here that any of these commands could touch by accident.

## Layout

- `crates/sim/` — `red-republic-sim`. All simulation. No renderer, no windowing, no engine. **This crate having zero engine dependencies is a rule, not an accident**: it is what kept the shell decision open, and it is what keeps it reversible now that one has been made.
- `crates/red-republic-shell/` — the `cdylib` holding the `gdext` bindings. **The only Rust that knows Godot exists.** Named at length on purpose: crate names shorter than about thirteen bytes trip a PDB-rename warning on Windows and silently break hot reload.
- `godot/` — the Godot project: scenes, `Control` layouts, themes, materials.
- **No `archive/`.** The frozen 1.x build was moved out on 2026-07-30 (`D:\archive` on Noah's machine). Read it for balance numbers and panel layout; never edit it, and never treat it as a specification. It is also still in this repository's history if the working copy is not to hand.

## Rules

- **Determinism, at two different bars.** Same seed and same inputs produce the same world; a save reloads bit-exact. **Map generation must reproduce across machines** — a shared seed is a promise between players — so it may not depend on anything platform-varying (transcendental precision, hash iteration order, address-dependent behaviour). **The running simulation need only reproduce for the same binary**, which is the easy case: Rust does not reassociate floats, so one compiler on one instruction set suffices. Nothing may enable fast-math-style float relaxation.

- **The save format must round-trip `f64` bit-exactly, and JSON does not.** Measured, not reasoned: 91,767 of 200,000 sampled `f64` values changed passing through `serde_json` — it writes correct digits and its *parser* is not correctly rounded. A simulation whose state is full of floats cannot use a format like that, and the failure is the worst kind: silent, one ULP, invisible until two runs have diverged far enough to notice. The format is `postcard` (bit patterns, not digits) and `the_save_format_round_trips_floats_bit_exactly` is the guard. **The crate owns the format** — `World::to_bytes`/`from_bytes`, not a serde value the caller encodes how it likes — because a requirement a caller can opt out of is not a requirement, and the guard would go on passing while testing a format nothing used. The version is decoded on its own before the world is parsed, so a save from a newer build reports that rather than "corrupt".

- **The determinism tripwire comes before the thing it defends.** v1's `save-roundtrip.test.ts` — serialize, reload, advance both 90 days, compare everything — is what caught every field someone forgot to persist. The equivalent test exists here before parallel scheduling is introduced, not after. A system schedule that is parallel and unordered is non-deterministic by default; explicit ordering is the fix and it must be defended by a test that would fail without it.

- **Systems propose, one writer applies, and each declares what it may change.** Carried forward from v1 because it is why blast radii stayed small: a system reads the world and returns what it wants to change; it never writes. There is deliberately no generic `{field, value}` escape hatch — that is "write anything" with extra steps, and it leaves a guard test nothing to check. Coarse operations are correct at genuine transaction boundaries (a border sale is stock out + contract credited + treasury paid + ledger booked, because those never happen apart). `systems::WRITE_SETS` names the mutation kinds each system may emit, and it is checked **in both directions**: a system may not emit outside its set, *and* a set may not claim more than the system emits. The second half is the one that rots — a write-set that has quietly become a superset constrains nothing and looks fine. **The player is now held to it too, and the gap it closed was wider than this file used to say.** It claimed every field on `World` was `pub`; measured, sixteen of seventeen were (`seed` was private) — but the field list was never the real surface. Every substruct also exposed `get_mut`, and `Building` has *every* field `pub` including `staff`, `powered`, `heated` and `work_done`, each documented "set by the X system, never authored". Counting the reachable entry points gave about **twenty-five**, among them `Buildings::demolish`, `Contracts::accept`/`decline` and `Fleet::commission` — player verbs with no `World` wrapper at all. This file also said the deliberate verbs were four; there were **five**, because `set_terrain` was one and was missed.

Every field on `World` is now `pub(crate)`. Systems are inside the crate and did not change; **outside it there are exactly two verbs — `tick` and `issue`**, and `command::Command` is what `issue` takes. An accepted command is recorded in the journal as it is applied and a refused one is not, because replaying a no-op is not replay. That is what finally gives the determinism rule's *same seed and same inputs* half an **inputs** to hold constant, and `a_republic_replays_from_its_own_journal` is the proof: a republic played through scattered commands, and a second one handed nothing but the journal, ending the same world byte for byte. The journal travels inside the save, so a save records how its republic came to be rather than only what it is — which is what makes a reported bug reproducible from the save alone.

A command returns `{ok, reason}`, and the reason is a sentence rather than a debug dump: 1.x's reason strings are what drove its toasts and its disabled-button tooltips, and retrofitting that is a known mistake this build gets to skip. The wording lives beside the error variants so a new variant cannot arrive without somebody deciding what it says.

**The one hatch, and why it is not one.** `tests/baselines.rs` needs to stand up ten thousand buildings and time the labour pass on its own, and neither is expressible through `issue` — measuring an axis through the player API measures every system at once and reports the wrong number confidently. `world::fixtures` exists for that behind the `fixtures` feature, which nothing that renders anything enables. **The enforcement is the compiler**: `src/bin/trajectory.rs` and `tests/baselines.rs` are separate crates held to exactly the boundary the shell is, which is why the trajectory runner now issues commands like a player. Verified by building a consumer that tries the old writes and watching all five fail to compile.

- **Metric, and honest about it.** Distance is metres, time is seconds; the day loop is a fixed timestep. **The word "tile" does not belong in simulation vocabulary.** v1 documented its own dishonesty here (`src/game/world.ts:233` in the 1.x build: a day covered ~5 tiles, so "any real-world unit here would be a fiction the sim cannot back") — this build exists partly to fix that. A vehicle's speed must be a quantity the simulation can actually stand behind.

- **Space is continuous; the grid describes terrain, not buildings.** Buildings sit at free positions with real metric footprints. There is no `tile.buildingId` occupancy model and no row-scan draw order — both were grid artefacts. Pathing is a graph over the road network, not a per-metre flood.

- **Resources are a 3D subsurface field, and the deposit is the thing — not the building.** Richness varies by position *and depth*; deeper costs more; volumes are finite and deplete on a long timescale (real coal deposits are enormous — depletion is a pressure, not a clock). Groundwater is a peer field from day one so wells are never a retrofit — and it stays one while water and sewage are deferred, which is exactly what makes that a deferral. Resources are invisible on the terrain and read through a **geological survey overlay**. A mine is an ordinary fixed-size building that **taps** a deposit and reaches the whole volume.

  **Two corrections from measuring this on 2026-07-28, both of which were prose describing something that does not exist.** "Extraction scales with how much machinery is pointed at it" is **not built**: extraction is `authored rate × day × staffing efficiency`, the rate is a flat 6 t/day on `CoalMine`, and nothing in the building table consumes `Machinery` at all — it is only ever a construction material. The only lever on extraction speed is siting more mines on the same body. And "depletion is a pressure, not a clock" is **false as tuned**: at 594 years to exhaust one body it is neither, and `Deposit::is_exhausted()` is a branch no playthrough reaches. The mechanic is presently decoration — the same shape as the bogging self-release that measurement caught, where both branches had passing tests and only one ever fired. **Making depletion visible needs roughly a 20× swing** (121 t/day to drain a body in thirty years, against 6 today), so it is a question about deposit size or industrial scale, and *not* one a machinery multiplier closes on its own. Undecided; do not tune either constant without re-reading this.

- **Citizens are individuals who live somewhere.** ECS entities with a home, a workplace, an age, a `Learning` (days of attendance and whether they are enrolled today), a `Wellbeing` (health and loyalty), and a real journey (`transport::Commute` — mode, distance and time, written by the labour pass alongside the workplace, because the two are one decision). **Work has to be reachable**: roughly 2 km on foot, further only with transport.

  **A per-person census is written every day and it is not free.** Health, loyalty and schooling all move daily, so `Mutation::Morale` and `Mutation::Schooling` are single coarse kinds carrying the whole population rather than four thousand separate mutations to express one pass. Enrolment is set *from the census wholesale* rather than toggled, because a university that loses its staff has to stop having students the same day — a mutation that could only enrol would leave graduates-in-waiting permanently out of the workforce of a republic that no longer teaches them.

  **Where order does not decide the answer, the population is walked unsorted.** A mortality or emigration roll is keyed by `(citizen, day)` from `LIFE_STREAM`, so *who* it picks is the same whatever order they were asked in; only the mutation's payload needs sorting, and a day's birthdays are a hundredth of the republic. Measured at 4,000 citizens: 26–27 ms per simulated day with four full sorts in the daily people pass, 25–26 ms with two. **Both of those numbers replaced wrong ones**, and the reason is worth carrying: the baseline suite runs its twelve tests concurrently, so the same axis read 45 ms while eleven other baselines were competing for the cores. **Run an axis on its own before believing a number moved.** v1's labour model had no geography at all — a citizen in the far south staffed a mine in the far north for free — and fixing that is what lets a mining town exist, and later die when its deposit runs out. That scenario, depletion plus commute together, is the acceptance test for the whole labour model — **and it is done**: `citizen::tests::a_mining_town_dies_when_its_work_does`, passing since the labour model landed. Named here because a scenario described without its test reads as an obligation and gets proposed as work over and over.

- **Transport lifts the reach ceiling physically, never by relaxing the rule.** A bus rides the road network, so it reaches exactly what the republic has built road to; it carries a finite number of people, so reach is a capacity you fund; and it burns fuel, so a commute is an ongoing cost against the same refinery output everything else wants. The bound is on **time** (45 minutes each way), which is what makes a faster road genuinely extend reach rather than merely shorten a trip. Walkers are always hired before riders — a seat spent on someone who could have walked is a seat denied to someone who could not. The counterpart to the mining-town acceptance test is `a_road_and_a_bus_save_the_town_the_mine_left_behind`.

- **Freight is vehicles, and a journey is a plan rather than a stepped simulation.** `FREIGHT_TONNES_PER_DAY` is gone. A lorry has a position, a load, a tank and a job, so a haul takes time proportional to distance, burns fuel the refinery output is already fighting over, and can be watched. The affordability comes from `journey.rs`: a moving thing carries waypoints plus a time window for the leg it is on, and **position is a pure function of `(plan, time)`** at any fractional tick — so a renderer interpolates smoothly at 60 fps while the simulation advances only in whole ticks, and the answer is identical at every game speed. Work happens at **leg boundaries, not per tick**: the per-tick cost is one float comparison per vehicle, measured at 7 / 12 / 38 ns for 6 / 48 / 144 vehicles. Stepping vehicles per tick was rejected on measurement, not taste — a one-second tick would need 1,982 ms of compute per real second at the fastest speed. `MIN_LEG_TICKS` floors every leg at one tick, which removes the zero-length-leg division and makes "at most one leg per vehicle per tick" a consequence rather than a rule.

- **Two 1.x fleet rules carried; the rest was re-derived.** **Garages own vehicles** — a Motor Depot's establishment is authored on `BuildingDef` beside everything else about it, and `crewed` says how many have drivers today, so wanting more lorries means another depot and sixteen more people. **A vehicle never accepts a job it cannot finish** — the round trip is priced at dispatch with the same planner that will drive it, so running dry is a refusal in the yard rather than a lorry stranded in a field. What is *not* carried is 1.x's speed unit: it was road-tile-equivalents per day and carried a comment admitting no real-world quantity could be recovered from it. **Roads are preferred, never required**: `journey::plan` costs the network route against the open-ground straight line and takes whichever is quicker, which is what makes a road something a vehicle chooses because it is faster.

- **A road is ordered, materialled, built, and undrivable until it is finished.** `RoadNetwork` is the finished graph; `roadworks::RoadSite` is one that has been ordered — a bill of materials per kilometre, builder-days, and a place lorries deliver gravel to. Nothing routes over a site, which falls out of keeping the two structures apart rather than from a flag. The existing `construction` system works road sites **from the same crew and in the same queue** as buildings: a building's id *is* its place in the commissioning order, and a road takes the count as it stood when it was ordered, so ordering a road takes its turn rather than jumping the queue or waiting behind every factory. Grades are authored (`Dirt` / `Gravel` / `Paved`) and a journey leg carries the **road's speed limit, not a flag** — a lorry does 25 km/h on a dirt track whatever it is capable of, which is what makes a grade a decision rather than a nicer word.

- **`Destination` is the widest interface in the freight half**, because a road site is a first-class delivery target. `World::consignee` is the one coarse view both the dispatcher and the UI read — position, held, capacity, and whether it is still a site — so neither has to know which kind of thing it is looking at.

- **Two rules that only coexist because a straight run is one leg.** Roads are laid with a junction every 200 m so buildings along them can reach the network (`ROAD_ACCESS` is 300 m), and every journey leg is floored at one tick. Taken together those give a subdivided road a ceiling of 12 km/h — **slower than the open ground beside it**, and the planner correctly refused to use any road at all. Waypoints exist to mark where something changes, and a junction on a straight road changes nothing, so `journey::plan` merges collinear same-speed hops into one leg. Found by measurement, and the reason `a_straight_road_is_one_leg_however_many_junctions_it_has` exists.

- **A site needs the materials for the work still to do, not its whole bill at every moment.** The bill is consumed in step with the work, so demanding the full bill continuously meant a site worked for one tick and then stalled until freight topped it back up — consuming twice the bill in total. That was invisible while freight was a scalar and a delivery landed the instant it was ranked; with lorries it is hours per top-up and a build-out crawls. The requirement now falls as the work is done.

- **A lorry does not roll for four kilograms, and getting that rule's escape hatch wrong cost a republic its diesel.** A scalar could serve a demand the instant it appeared for free; a fleet cannot. A farm making six tonnes a day holds four *kilograms* a tick after the last collection, and dispatch sent a lorry for it — every tick, with every lorry. `MIN_LOAD` is the fix: let it accumulate, then send one lorry. Two exceptions, and **both had to be narrowed after measurement**: a **site** is served whatever the quantity (its bill of materials is finite and one-off, so a building needing one tonne of machinery would otherwise never open), and a **blocked yard** is cleared only when the trip actually empties it — waiving the minimum for any full bin waived it permanently, because a producer feeding a consumer sits at its cap by definition. The related trap: **`serve` must try every yard in distance order, not only the nearest**. Treating the closest as the only one meant the republic's clothes ran out with fifty tonnes standing five hundred metres further away, because the depot next door had 1.99 t left.

- **Not every system runs every tick.** Labour is daily — people do not change jobs every minute — and running it per tick cost 656 ms per simulated day at only 4,000 citizens, against 1 ms once moved to the day boundary. Contracts are daily for a harder reason: deadlines are day indices, so a per-tick sweep would fine a republic 1,440 times for one missed delivery. That first figure was found by `tests/baselines.rs`, not by reasoning, which is the argument for having it. When adding a system, the first question is what cadence it actually needs; the consequence is real and belongs in a test (people start work the day *after* they arrive).

- **Measure, never estimate.** Performance claims get a recorded baseline before any optimisation: agent counts, pathing cost per simulated day, geology query cost, worldgen and the founding shelf. v1's habit of pinning real measurements in tests (`mapgen-save-performance`, `logistics-routing-performance`) is why its performance conversations were about facts. It keeps paying: `simulated_day_cost` caught the households system calling `residents_of` once per home per tick, each call rebuilding and sorting the whole population — **212 ms per simulated day at 4,000 citizens, 23 ms once counted in one pass**, and it went from quadratic-ish to near-linear. Nothing about that code looked wrong.

- **The ground is state, and the thaw is not written down anywhere.** Precipitation is authored per climate beside the temperature, and it is bursty — three days in ten carry the month's water, because a month smeared evenly never saturates anything. `ground.rs` turns that into soil: snow lies below freezing and melts above it, meltwater goes into the topsoil like rain, and frost lags the air because soil has thermal mass. Nothing in it mentions a season and **the worst going of the year comes out a few weeks into spring on its own**. Frozen ground is hard however wet it is, so midwinter is *better* cross-country going than the thaw — the counter-intuitive half, and the one with its own assertion. This departs from the plan, which wanted softness as a pure function of a recent window: a window long enough to hold a winter's snow costs sixty substream draws per query and cannot express the carry that makes a thaw. `Ground::forecast` keeps what purity was for — rolling the same recurrence forward off the pure weather functions moves nothing.

- **The ground holds two different bodies of water, because a lorry and a root are asking different questions.** `moisture` is the topsoil: it decides whether a vehicle sinks, and it is *gone* ten days after rain. `water` is the root zone — four times the reservoir, an eighth the drying rate. **This is a measured distinction, not a modelling flourish.** Reading crop yield off `moisture` killed every harvest in every climate: across the 188 days a year warm enough to grow anything its median is 0.000 and its p75 is 0.088, because summer evaporation empties the top few centimetres between rain bursts. No threshold could have fixed that — the harvest would still have hinged on which day a burst landed. **The signal was wrong, not the constant**, which is the sweep rule's third shape arriving in a place nobody was sweeping.

- **A farm answers to the ground and the air; nothing in it reads the month.** `systems::growing_conditions` gates on frost, ramps with today's temperature, and scales with root-zone water — so winter yields nothing because it is frozen and cold, and a cold snap in May does the same thing without a special case. Same discipline as the thaw. Drought has a **floor** rather than running to zero, and that floor is why the Southern Steppe is playable: it sits at a growing-season median of 0.029, so a curve reaching zero would have made one of the four postings agriculturally impossible — a balance hole wearing a design consequence's clothes. **What fell out unplanned is agricultural geography**: steppe dry and long, taiga wet and short, maritime long and wet, plains in between. Nobody authored that; it comes from the climates that were already there.
  **The balance consequence, stated because it is real and unresolved:** a seasonal farm makes roughly 790 crops a year against a Food Factory's 900 t appetite, where a year-round one made 2,160. **One farm no longer feeds one factory**, and `scenario::found` still places one of each, so every founding is now short. Left as it is rather than tuned — `fed%` has no consequence attached yet, so nobody starves, and softening a start is exactly what the goal forbids.

- **Machinery is the industrialisation tax, and it wears in proportion to work.** `BuildingDef::wear` is tonnes per day at full activity, authored on all 28 rows; it lands inside `efficiency`, so an idle building wears nothing and a farm that cannot grow wears nothing either, with no special case for either. **A dry bin is a soft penalty and never a stall** — `WORN_EFFICIENCY` is 0.5, ported verbatim, because a republic that runs out of machinery must limp rather than stop: limping is recoverable and stopping is not. Deliberately *not* folded into the input shortfall factor, which throttles toward zero. **The standing machinery demand this was said to create now has a customer.** A Construction Office owns the plant its gangs work with, and that plant wears at `MACHINERY_PER_BUILDER_DAY` — charged to the office, in proportion to builder-days actually worked, so an office with idle crews wears nothing and one with no crews out wears nothing at all. A dry bin halves the work and never stops it, which is `WORN_EFFICIENCY` applied where it was always going to be needed. **The office's `wear` field is authored `0.0` on purpose**: a flat daily rate on top would charge a republic for diggers standing in the yard. That is the first thing in this game that has ever wanted `Machine Works` to exist.

- **Vehicles cross country over a lattice of their own, at 100 m.** Ten thousand cells on a 10 km map against the terrain's million: that gap is what makes off-road routing affordable, and it is why the lattice is a separate structure rather than a field on the terrain. What varies at ten metres is where a building can stand; what varies at a hundred is where a lorry would rather drive. **Anything that replaces the terrain must go through `World::set_terrain`**, which rebuilds the lattice — setting one without the other leaves vehicles routing over a map that is no longer there, and the symptom is a republic where nothing can get anywhere for no visible reason.

- **A crossing is a deterministic margin and then a roll, and both halves earn their place.** Demand is the going along the leg times what the load costs; margin is the vehicle's capability less that; below zero the odds climb with how far below, and stop short of certain. The roll is keyed by `(vehicle, leg, day)` from `BOG_STREAM`, so it is a pure function — the same run sticks the same lorry in the same field, and **the odds are showable** (`World::bog_chance`), which is most of the explicability a probability model normally costs. Roads never bog: that is the whole argument for building one. The roll happens wherever a leg *begins* — at a leg boundary, on setting out from a loading bay, at dispatch, and at each day boundary for a vehicle already out — because a short haul is a single leg and would otherwise never be tested at all.

- **Both ways out of a bog are live, and the second one had to be added on measurement.** The designed rule was that a vehicle frees itself when the ground comes back and a recovery vehicle forces it otherwise. Measured over a simulated year, *every single* casualty was towed: a vehicle bogs precisely when the going is bad, and the going stays bad for weeks afterwards, so the deterministic rule never fired. A marginal bogging is now treated as what it is — bad luck rather than bad ground — and the crew digs out over a few days, while one that went well past what the vehicle could take still needs a tow. Delaying the tow was tried first and rejected on measurement: at two, three and five days it bought almost no extra self-releases and more than doubled the days a republic had a lorry standing in a field. **Recovery is never a button** — it is a Recovery Vehicle that drives there and burns diesel — and the tow sets the casualty down at the *far* side of what beat it, or the rescue is a coin flip away from being needed again immediately.

- **Traffic wears the ground, and a worn corridor becomes a road nobody ordered.** Every off-road leg packs down the lattice cells it crossed, in proportion to the load. Packing lowers the cost of a cell, which concentrates traffic on it, which packs it further — and **the loop needs damping or it runs away**. Two things bound it: packing saturates at a made track rather than improving for ever, and a corridor past the threshold is promoted *out* of the lattice into `RoadNetwork` as Dirt segments, after which traffic rides a road leg, stops packing the cells, and lets them fade. A road is not worn by the lorries riding it, which is what stops a road from wearing itself into a better road. Wear also **fades daily**, so a corridor has to be kept — without that, every line any lorry ever drove is permanent and the map fills with the ghosts of routes nobody uses. Measured on the founded republic: 14 km of track in six months, then a plateau. `WEAR_PER_PASS` and `WEAR_FADE_PER_DAY` are first-pass and are the knobs to feel that rate out on.

- **Weather is state, not the calendar.** Heating demand follows **today's temperature**, never the month — that was v1's explicit rule and it is what makes a cold snap an event a republic can be caught out by. Temperature is a pure function of `(seed, climate, day)` drawn from its own substream, so reading a forecast never perturbs the economy and any future day can be asked about without advancing anything. Climates are authored as twelve monthly means rather than a sinusoid: exact arithmetic, and a table can express a late spring that a symmetric curve cannot.

- **Balance lives in data, behaviour lives in systems.** A list of entity ids inside simulation logic is a smell: a list is a thing you must remember to edit, and whatever you forget lands silently in a fallback. Author the property next to the fields it relates to, and add a guard test so an unauthored case fails the build instead of defaulting quietly. Every field on `BuildingDef` is authored on **every** building for exactly this reason — `heat: 0.0` on a sawmill is a decision somebody made, and a defaulted one would not be.

- **The order things are founded in is a staffing priority.** Labour fills workplaces in commissioning order, so whatever is built last is what goes unmanned when the republic is short of people. That is a real consequence and `scenario::found` is written against it: heat, power **and haulage** are placed together, ahead of the shops — since freight became physical, a republic without a staffed garage starves beside its own full bins. A founding with fewer settlers than jobs is a legitimate hand — but it will be the tail of that list that stands idle, and the trajectory runner is how you find out which.

  **And the tail is the customs house, which turns a hard start into half a game switched off.** Raising the Construction Office from ten workers to twenty took the founding from 124 jobs to 134 against 120 settlers, and the house went from half-staffed to empty: a republic that could not clear a single tonne through its own border, in a change that was about construction and said nothing about trade. The trajectory runner had been printing a flat zero in the money column and it read as balance. **`scenario::SETTLERS` is now the founding hand and `the_founding_hand_can_staff_itself` is the guard** — Moscow does not send a building and withhold the people to run it. It is *exactly* enough and no more, so the first thing the player commissions still stands unstaffed until the republic grows. The guard checks both halves, because counting up correctly is not the same as everyone being able to walk to work.

## Design decisions already made

**Founding is choosing your land**, in two beats, and it replaces both v1's new-game dialog and its generic intro overlay:

1. **The land** — a shelf of candidate maps derived from one master seed, shown as comparable minimaps over a full-screen stage rendering the selected candidate with its real climate. Filters (size, climate) **transform the same seeds** rather than replacing them, so changing climate shows what it does to land already under consideration. Cards carry the picture plus the few stats that actually decide a start — visible because Moscow surveyed before assigning the posting.
2. **The posting** — republic name, and a briefing specific to the map chosen. **No difficulty setting**: the land is the difficulty, and the goal section says why. An earlier draft of this line named three presets independent of land quality; it was never implemented, and it was cut on 2026-07-28.

Land quality genuinely varies; nothing guarantees a rich start.

The sim-side half is built (`founding.rs`): `Shelf::derive` gives six candidates from one master seed, each with the decisive stats read from the **engine-owned** survey — never recomputed, so a card cannot advertise a republic the player will not be given. Re-filtering keeps the seeds and re-derives the land. I had told noahs during the interview that it was essentially free, reasoning from v1's tile generator, and it is not.

**The cost recorded here was attached to the wrong map size, and the correction is the interesting part.** Measured 2026-07-29 by `founding_shelf_cost`: a shelf of six costs **219 ms at 6 km, 611 ms at 10 km, and 1,630 ms at 16 km**, with a re-filter costing the same again. The "220 ms for six 10 km candidates" this line used to claim is what a **6 km** shelf costs — and 10 km is `SIZES[1]`, the default, so the screen a player opens by default was recorded as nearly three times cheaper than it is. Verified as pre-existing rather than a regression by measuring the same axis on `main`. Nothing about the design changes; what changes is that the loading state is unavoidable at every size rather than a nicety at the largest.

**A candidate now keeps the world it was surveyed from** (`Candidate::world`), which is what lets the screen render the selected posting in full, and it makes `Shelf::found` hand over *that* world rather than building a second one from the same spec and trusting it to match. Worldgen determinism is still asserted, deliberately now that nothing depends on it: `the_same_spec_generates_the_same_land_twice`, because an assumption that stops being load-bearing is one that stops being noticed when it breaks. The price is transient memory, measured rather than estimated: **11.5 MB at 6 km, 31.6 MB at 10 km, 81.3 MB at 16 km**, all freed when a posting is chosen.

**Six speeds, and one of them is the point.** 0 paused, then **1 = real-time — one real second is one in-game second** — then 1 second to 1 / 2 / 4 / 8 in-game hours. The simulation half is already built for it: `Journey::position_at` makes a vehicle's position a pure function of `(plan, time)` at any fractional tick, so a renderer interpolates at 60 fps while the simulation advances in whole ticks, and `a_journey_is_the_same_wherever_you_sample_it` proves every setting draws the same world. Recorded here on 2026-07-28 because it had been decided in conversation and written down nowhere — the failure this section exists to prevent. Real-time is the thesis (see the goal), so the shell has to earn it rather than merely offer it.

**Terrain grid resolution is 10 m, and that was decided by measurement.** The sweep (`cell_size_sweep`) found a clean quadratic with no cliff anywhere, so performance does not choose a resolution — the correctness floor does. 10 m is the coarsest size at which the smallest building in the table still covers a cell in both axes; below it a house and a shop become the same rounded square, which is the grid artefact this build exists to remove. The price is 4.8 MB and 36 ms per 10 km map. Resolution is carried on the `Terrain`, not in a constant, so re-measuring stays a one-line experiment and a save always knows what it was written at.

## The shell: Godot 4.7.1 driving a Rust simulation

**Decided 2026-07-27**, at the decision point the plan named and on the evidence it asked for. The simulation stays exactly as it is; Godot renders it and takes input.

**The version in this heading was 4.6 and was wrong** — the engine on this machine is **4.7.1**, installed through Steam. gdext 0.5 compiles against API 4.6 and runs on the 4.7.1 runtime, because the forward-compatibility rule is *runtime ≥ API*; the `Initialize godot-rust (API v4.6.stable.official, runtime v4.7.1.stable.steam)` line at startup is the proof it loaded. **A Steam install auto-updates**, which can break the build with no commit to blame. **CI pins a standalone 4.7.1 from godotengine.org and this desktop does not** — an earlier version of this line said "the build pins a standalone", which was an intention written in the past tense and was false for a while. Both CI jobs that touch Godot download the pinned build, and the `package` job pins the export templates and Inno Setup with it, so the artifact is reproducible. Every render, screenshot and frame measurement still happens against the auto-updating Steam copy, because that is what is installed here.

- `crates/sim/` — unchanged. **Zero engine dependencies, still a rule.**
- `crates/red-republic-shell/` — a `cdylib` holding the `gdext` bindings. **The only Rust that knows Godot exists.**
- `godot/` — the Godot project: scenes, Control layouts, themes, materials.

**Why, in one line: the deciding axis was UI, and it was never close.** This game is roughly half UI — stockpile tables, per-building detail, delivery-priority panels, the founding shelf — and dense, themed, data-heavy UI is precisely what Godot's Control nodes are good at and precisely what every Rust option is weakest at.

What the re-check found, against what was recorded before it:

- **`bevy_feathers` is explicitly editor and inspector tooling, deliberately not for game UI.** The plan had recorded it as evidence Bevy's UI was maturing. It is not evidence of that, and removing it takes most of the case with it. Independent 2026 assessments still say Bevy is hard to recommend for UI-heavy games and that no crate has proven out a high-level API for declaring UI trees.
- **The flagship evidence collapses on inspection.** Tiny Glade is cited as Bevy's shipped game; it uses `bevy_ecs` and **its own renderer**. So it is not evidence for Bevy's renderer or UI — it is evidence for the architecture this project already has. There is still no large simulation game on Bevy's full stack.
- **Bevy's churn is acknowledged upstream**, including by the project lead. Quarterly breaking changes are a recurring tax; levied on the weakest part of the stack, in the half of the game that is that part, it compounds.
- **egui is not the escape hatch.** Single-pass immediate-mode layout makes dynamically-sized and responsive layouts hard or impossible, and it is best suited to overlays rather than dense data UI.
- **A hand-written wgpu shell founders on the same rock.** Total control over the simulation is what matters and this project already has it; control over a UI toolkit buys nothing this game needs. Writing a themed widget system from scratch is the most expensive and least differentiated work available.

**Determinism is better under this split, not worse.** The engine never touches simulation state — Godot calls `tick()` and reads. Under Bevy there would be standing temptation to put simulation components in the engine's `World` and let a plugin write them, which is the CS2 failure mode in miniature.

**The cost, stated plainly:** a marshalling boundary, and this UI reads a lot. It is survivable because the heavy transfers are one-off or event-driven (terrain mesh at load, buildings as a MultiMesh updated on change) while per-frame traffic is a camera and a few panels — and because the sim already exposes coarse engine-owned views (`Geology::survey`, `stall_reason`, `cover_days`, `Shelf`) built so the UI never recomputes anything. **Those views are the marshalling surface. Keep them coarse; that discipline is now load-bearing for performance as well as for correctness.**

**What would reverse this:** a fat per-frame marshalling surface, or Godot handling a million-cell heightmap badly. The sim is untouched either way, which is what the zero-dependency rule bought.

**Probed 2026-07-28, and neither fired.** A throwaway gdext probe — the real sim behind a `Node3D`, a real 10 km / 10 m terrain as one `ArrayMesh`, 2,000 building instances in a `MultiMesh`, vehicles moved every frame, camera orbiting, vsync off, 600 frames on an RTX 4060 Ti:

| | |
|---|---|
| terrain build + upload, 1,996,002 tris | **30 ms**, one-off |
| every height read through the public `height_at` | **3.2 ms** for 1,000,000 calls |
| 2,000-instance MultiMesh write | **0.5 ms** |
| frame p50 / p95 | **0.37 ms / 0.50 ms** — 2.2% of a 60 fps budget |
| per-frame vehicle read, interpolated | **0.9 µs** |
| first frame | **146 ms** — pipeline compile, so a load screen is real |

**What this settles.** The two conditions written above: the heightmap is comfortable and per-frame marshalling is free, which also means **`Terrain` needs no bulk accessor** — the private `Vec<f32>` behind `height_at` was assumed to be a problem and measured not to be. It does not test a real terrain shader (one flat material, no LOD, no splatting, no water), a weaker GPU, or the sim at scale — the republic here had 16 buildings and 7 vehicles, and the other 1,984 instances were synthetic transforms testing the renderer alone. Composing the probe against the existing `simulated_day_cost` baseline puts a 615-building tick at ~0.07 ms, so sim plus render lands near 0.44 ms — but that is two measurements added together, not one observed.

### The UI axis, probed separately — because that is the axis the decision was made on

The heightmap probe contained no UI, and dense themed `Control` layouts are the *reason* Godot was chosen. Swept a themed stock-ledger panel over the same live 3D scene, refreshing **every label from simulation state every frame**, 400 measured frames per level:

| rows | labels | build | frame p50 | `set_text` p50 |
|---|---|---|---|---|
| 0 | 0 | 3.9 ms | 0.39 ms | — |
| 50 | 250 | 11 ms | 0.39 ms | 44 µs |
| 200 | 1,000 | 44 ms | 0.47 ms | 162 µs |
| 500 | 2,500 | 112 ms | 0.80 ms | 403 µs |
| 1,000 | 5,000 | 229 ms | 1.39 ms | 816 µs |

**A clean linear gradient with no cliff anywhere**, which is the shape that says tune it rather than replace it. Per-frame cost is ~0.2 µs per label and **`set_text` is nearly all of it** — the cost is text shaping, not layout or draw, and a real panel does not change five thousand numbers a frame. At the density a 615-building republic actually needs, a visible table costs **0.08 ms over baseline**, half a percent of a frame.

**The one architectural consequence: build cost dominates, at ~46 µs per label — 165× the per-frame cost.** Opening a panel that instantiates 5,000 `Label` nodes is a visible 229 ms hitch, while updating them is free. **Virtualise long lists — build nodes for visible rows only, or pool them.** That is a design rule for the shell, not a tuning note.

Verified by looking at it, not only by the numbers: the panel renders real building names, staff counts and POWERED/DARK states over a terrain that is genuinely in frustum. A probe that drew nothing would have reported excellent frame times. **Still untested:** `Tree` / `ItemList` / `Button`, nested and scrolling containers, a real theme resource, and input handling — this was `Label` in a `GridContainer` with one StyleBox.

### The shell as built, and what a rendered frame caught that numbers did not

`crates/red-republic-shell` and `godot/` exist. The republic is a `Node3D`; Godot calls `tick()` and reads. Six speeds, the terrain as one `ArrayMesh`, buildings as a `MultiMesh` uploaded only when the count changes, vehicles interpolated per frame through `Journey::position_at`, and roads drawn from `RoadNetwork::segments`.

**Measured on the founded 6 km republic, vsync off, 600 frames:**

| speed | frame p50 | frame p95 |
|---|---|---|
| 0 paused | 0.65 ms | 1.30 ms |
| 1 real-time | 0.61 ms | 1.27 ms |
| 5 (8 h/s) | 0.61 ms | 1.29 ms |

**Flat across every speed** — about 4% of a 60 fps budget with the simulation genuinely running. At this size the renderer is not the constraint and neither is the tick.

**Three bugs got through every number and were caught only by looking at a rendered frame**, which is the argument for `-- --shot <path>` existing as a permanent check rather than a one-off:

- **The terrain rendered as nothing at all.** 361,201 vertices uploaded, no errors, an empty frame. The triangles were wound clockwise, so the entire map faced downwards and was culled. Nothing that counts vertices can see this.
- **The camera aimed at the map's corner.** `look_at_from_position` takes **global** coordinates and it was handed the rig's local origin, which is world zero. The republic sat in the bottom-right of the frame with half the screen empty.
- **The camera framed the map rather than the republic.** A posting is sited on the shallowest coal body, so it is routinely nowhere near the middle — framing the map means opening on empty ground.

A fourth thing was not a bug and is worth recording because it looked like one: the ground appeared perfectly flat. Measured, a 6 km map has **64.7 m of relief** and a 10 km map has 82.2 m. It read flat because the placeholder albedo was fully saturated. The fix was the material, and it is why `terrain.gdshader` reads a one-hot surface channel out of vertex colour rather than Rust deciding what grass looks like — **the art direction has to be changeable without recompiling the simulation's renderer.**

**The game renders under the OpenGL 3 compatibility driver, which is the closest thing here to testing "no crash on a GPU nobody here owns".** `--rendering-driver opengl3` was run and the frame *looked at*: terrain, buildings, roads, power lines and the whole HUD draw, with flatter lighting and washed-out ground because the tonemapping differs. That is a real fallback rather than a broken one, and it matters because Forward+ needs Vulkan and the machine this is built on has it. **What is still unverified is whether Godot falls back on its own** when Vulkan is missing, rather than failing to start — nobody here has a machine to find out on, so the escape hatch a stranger would need is a command-line flag they cannot read if the game will not open. That is the honest state of the GPU clause: the renderer is fine, the *fallback path* is untested.

**Correcting a recorded fact:** the PDB-rename warning was noted as something a crate name of ~13 bytes or more avoids. It does not. `red_republic_shell` is 18 bytes and still trips it, because the check is against the **path** the DLL embeds, and the replacement name is always longer than the original. It is cosmetic and costs hot reload; it is not a naming rule.
